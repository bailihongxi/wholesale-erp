# 页面模块顺序规范（硬性）

> 老板 2026-09-24 指令：**系统设定，所有模块的「已选商品明细」模块都要位于「搜索/选择商品」模块的上边。**
> 举例：采购单里「已经选好的产品模块」要在「商品明细列表」上部，便于阅读与确认。
> 本文件是唯一口径，与任何页面现状冲突时以本文件为准。

---

## 一、规定（写死）

### 规定 1：已选明细在上，商品选择在下

凡页面同时存在「**已选商品明细**」与「**选择/搜索商品**」两个模块，
**已选明细模块必须排在商品选择模块之前（页面上方）**，电脑端与手机端一致。

| | 上方 | 下方 |
| --- | --- | --- |
| ✅ 正确 | 已选明细（含合计） | 选择 / 搜索商品 |
| ❌ 错误 | 选择 / 搜索商品 | 已选明细 |

**为什么**：选完一批商品后，视线要立刻能回到"我已经选了什么、合计多少"，
再继续向下挑。反过来放时，手机上长长的商品列表会把已选明细顶到屏幕外，
每加一件就要往上翻回去确认 —— 容易多选、漏选、重复选。

### 规定 2：用 DOM 顺序实现，不用 CSS `order`

顺序调整一律改**模板里模块的先后**，不要靠 `flex order` / `grid-row` 之类的视觉重排。
原因：屏幕阅读器与键盘 Tab 焦点按 DOM 顺序走，CSS 重排会造成"看到的顺序"与
"焦点顺序"不一致；手机端也没有额外样式要维护。

### 规定 3：两端同序

电脑端与手机端显示同一份 DOM 顺序（卡片 / 列表只是同一份数据的两种呈现），
不为手机端单独再排一次序。

### 规定 4：操作按钮留在最后

「清空 / 提交 / 确认」这类整单操作按钮放在**商品选择模块之后**（页面底部），
与采购开单页保持一致；不要插在已选明细与选择器中间。

## 三、落地前必查

1. 模板里「明细」区块是否写在 `<ProductPicker ... />` **之前**；
2. 明细为空时的提示文案是否跟着改（选择器在下方就说**下方**，别再写"上方"）；
3. 电脑端（≥1280）与手机端（390）各看一眼顺序是否一致；
4. 跑 `tests/module-order.test.ts` —— 它会静态扫描上表 6 个页面，顺序反了直接红。
