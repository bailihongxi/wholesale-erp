# 修改功能复用方案（从销售单归纳）

> 来源：销售单详情页（V2.0-25）「修改」功能
> 目标：把销售单**电脑版 + 手机版**的「修改」功能、排版、页面显示抽成通用件，
> 让采购单 / 报价单 / 出入库单等其它单据页直接套用，不再每个页面各写一遍样式和滚动逻辑。

---

## 一、归纳出什么（两个可复用件）

| 文件 | 作用 | 解决什么 |
| --- | --- | --- |
| `src/composables/useEditMode.ts` | 编辑态**状态机** | `showEdit` / `saving` / 进入编辑时的滚动 / 关闭后的滚动，各页面重复写 |
| `src/components/EditModePanel.vue` | 编辑**面板组件**（布局 + 底部操作条 + 内容样式） | 电脑端内联 vs 手机端全屏的排版、`.ec-*` 可编辑卡片样式、取消/保存按钮条 |

销售单详情页本身**保持不动**（它是这套模式的参考实现，且有 `tests/sale-order-mobile-cards.test.ts` 锁着行为），
新页面直接引用上面两个件即可。

---

## 二、模式要点（核心 4 条）

### 1. 状态机统一：`showEdit` 一个开关管两端

```
详情页 View  ──showEdit=false──▶  展示态（底部橘色「返回」键）
            ──showEdit=true ──▶  编辑态（EditModePanel，返回键被 v-if 收起）
```

- `startEdit()`：先拷出可编辑副本（`editItems` / `editRemark`），再置 `showEdit = true`。
- `closeEdit()`：**取消**和**保存成功**都走它（避免两处各写一次 `showEdit=false` 漏一处）。

### 2. 电脑端 / 手机端两套显示形态，共用一份 DOM

| | 电脑端（≥768px） | 手机端（≤767px） |
| --- | --- | --- |
| 编辑模块位置 | **内联**在详情页下方，当作普通卡片（同宽、同圆角、同阴影） | `position:fixed` **整屏覆盖**，`z-index:90` |
| 边框 | 无橘色大边框（V2.0-25 已去掉 4px `--c-amber`） | 无边框，满屏 |
| 内容区 | 随页面滚动 | `.edit-scroll` 独立滚动，底部按钮常驻 |
| 底部按钮 | 「取消」「保存修改」卡片式（取消占 1 份、保存占 2 份） | 贴底通栏，两键各占一半，带 `safe-area` 内边距 |
| 可编辑明细 | `display:contents` 让「序号+商品名+数量+单价+金额」排成**一行** | 上下两行（上行名称/金额，下行两个输入框） |

> 关键：**不要**为电脑端单独维护一套表格 DOM。两端共用 `.ec-*` 卡片 DOM，只在 CSS 里改排布。

### 3. 底部只放「取消 / 保存修改」——返回语义交给详情页

- 编辑模块里**不再放返回按钮**（V2.0-25 已删掉橘色 `btn-back`）。
- 详情页底部那颗橘色「返回」键是 `PageActions`：

  ```html
  <PageActions v-if="!showEdit" cancel-text="返回" @cancel="goBack" />
  <EditModePanel :model-value="showEdit" ... />
  ```

  编辑时它被 `v-if="!showEdit"` 收起；**模块一关就自动回来**——这就是用户要的「取消/保存后模块关闭，橘色返回键继续出现」。

### 4. 滚动接管（避免「点了没反应」和「关掉后停在空白」）

| 时机 | 行为 | 为什么 |
| --- | --- | --- |
| `startEdit()` 后 | 仅电脑端：`scrollIntoView` 到编辑区（`.edit-page`） | 编辑区在页面下方，不滚会像没反应；手机端全屏覆盖，无需滚 |
| `closeEdit()` 后 | `scrollIntoView` 到 `.page-actions`（详情页底部操作栏） | 关掉后页面变短，视口可能停在空白；顺带把刚恢复的橘色返回键带进视野 |

## 三、API 速查

### `useEditMode(options?)`

```ts
const { showEdit, saving, startEdit, closeEdit } = useEditMode({
  scrollSelectorOnStart: '.edit-page',  // 可选，默认不滚；仅 ≥768px 生效
  scrollSelectorOnClose: '.page-actions' // 可选，默认 '.page-actions'
})
```

| 返回 | 类型 | 说明 |
| --- | --- | --- |
| `showEdit` | `Ref<boolean>` | 编辑态开关，绑给 `EditModePanel` 和 `PageActions` 的 `v-if` |
| `saving` | `Ref<boolean>` | 保存中，绑给面板的 `saving` prop 禁用按钮 |
| `startEdit()` | `() => Promise<void>` | 置 `showEdit=true` + `nextTick` + 滚动（拷贝副本请在调用前做） |
| `closeEdit()` | `() => Promise<void>` | 置 `showEdit=false` + `nextTick` + 把 `.page-actions` 滚回视野 |

### `<EditModePanel />`

| Prop | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `model-value` | `boolean` | — | 是否显示（绑 `showEdit`） |
| `saving` | `boolean` | `false` | 保存中，禁用两个按钮并把保存键文案换成「保存中...」 |
| `cancel-text` | `string` | `'取消'` | 取消按钮文案 |
| `save-text` | `string` | `'保存修改'` | 保存按钮文案 |
| `saving-text` | `string` | `'保存中...'` | 保存中按钮文案 |

| 事件 | 触发 |
| --- | --- |
| `cancel` | 点「取消」→ 页面调 `closeEdit()` |
| `save` | 点「保存修改」→ 页面执行保存逻辑，成功后调 `closeEdit()` + 重新加载 |

## 四、Quick Start（可直接抄的骨架）

**模板**

```html
<!-- 编辑态：一行搞定（电脑端内联 / 手机端全屏由组件内部 CSS 切换） -->
<EditModePanel :model-value="showEdit" :saving="saving"
               @cancel="closeEdit" @save="onSaveEdit">
  <!-- 头部卡片 -->
  <section class="block">
    <div class="d-head"><h3 class="d-no">修改采购单</h3></div>
    <div class="d-meta remark-row">
      <div class="rm-label"><i>备注</i></div>
      <div class="rm-input">
        <textarea v-model="editRemark" class="edit-remark-input" rows="2"
                  placeholder="选填" @input="onRemarkInput"></textarea>
      </div>
    </div>
  </section>

  <!-- 可编辑明细卡片 -->
  <section class="block">
    <h4 class="block-title"><span class="bar"></span>商品明细（{{ editItems.length }}）</h4>
    <ul class="ec-list">
      <li v-for="(it, i) in editItems" :key="i" class="ec-item">
        <div class="ec-top">
          <span class="ec-idx">{{ i + 1 }}</span>
          <span class="ec-name">{{ productMap[it.productId]?.brand }} {{ productMap[it.productId]?.model }}</span>
          <b class="ec-amount">¥{{ money((it.quantity || 0) * (it.price || 0)) }}</b>
        </div>
        <div class="ec-row">
          <label class="ec-field">
            <i>数量</i>
            <input v-model.number="it.quantity" type="number" min="1" inputmode="numeric" class="ec-input" />
            <em>{{ unitOf(it.productId) }}</em>
          </label>
          <label class="ec-field">
            <i>单价</i>
            <input v-model.number="it.price" type="number" min="0" inputmode="decimal" class="ec-input" />
          </label>
        </div>
      </li>
      <li v-if="!editItems.length" class="empty">暂无明细</li>
    </ul>
    <div v-if="editItems.length" class="mc-total">
      <span>合计</span>
      <span class="mt-qty">{{ editItems.reduce((s, it) => s + (it.quantity || 0), 0) }} 件</span>
      <b class="mt-amount">¥{{ money(editItems.reduce((s, it) => s + (it.quantity || 0) * (it.price || 0), 0)) }}</b>
    </div>
  </section>
</EditModePanel>

<!-- 展示态：返回键（编辑时被收起，模块一关自动回来） -->
<PageActions v-if="!showEdit" cancel-text="返回" @cancel="goBack" />
```

**脚本**

```ts
import { useEditMode } from '../../composables/useEditMode'
import EditModePanel from '../../components/EditModePanel.vue'

const { showEdit, saving, startEdit, closeEdit } = useEditMode({ scrollSelectorOnStart: '.edit-page' })
const editItems = ref<Array<{ productId: number; quantity: number; price: number }>>([])
const editRemark = ref('')

/** 点「修改」：先拷副本，再进入编辑态 */
async function beginEdit(): Promise<void> {
  editItems.value = items.value.map(it => ({
    productId: it.productId, quantity: it.quantity, price: it.price
  }))
  editRemark.value = order.value?.remark || ''
  await startEdit()
}

/** 点「保存修改」 */
async function onSaveEdit(): Promise<void> {
  if (!order.value) return
  saving.value = true
  try {
    const res = await purchaseStore.updateOrder(Number(route.params.id), editItems.value, editRemark.value)
    if (res.ok) {
      showToast('已保存')
      await closeEdit()      // 关闭模块（橘色返回键自动回来）
      await loadOrder()      // 重新拉数据
    } else {
      showToast(res.message)
    }
  } finally {
    saving.value = false
  }
}
```

## 五、组件已内置的 class（slot 内容直接用，不用再写样式）

| class | 用途 |
| --- | --- |
| `.block` / `.block-title` / `.bar` / `.d-no` / `.d-meta` / `.rm-label` | 编辑页头部卡片、备注行（沿用全局卡片观感） |
| `.edit-remark-input` | 备注 textarea（随内容自增，需页面自己调 `autoGrowRemark`） |
| `.ec-list` / `.ec-item` / `.ec-top` / `.ec-name` / `.ec-idx` / `.ec-amount` | 可编辑明细卡片列表 |
| `.ec-row` / `.ec-field` / `.ec-input` | 带「数量 / 单价」标签的输入框（触摸目标 ≥44px） |
| `.mc-total` / `.mt-qty` / `.mt-amount` | 编辑态合计条（手机端没有表格 tfoot，用它补上） |

> 组件用 `:deep()` 承载这些样式，且全部以 `.edit-page` 为作用域前缀 ——
> **引入本组件不会污染页面其它区域**，页面里 `<table>`、`.item-table` 等旧样式不受影响。

## 六、迁移指南（以采购单 `PurchaseOrderDetailView.vue` 为例）

### 现状问题

1. `.edit-page` 是**无条件** `position:fixed` 整屏覆盖 —— 电脑端也被强制全屏，和详情页版面脱节。
2. 底部有 **3 个按钮**（`btn-back` 返回 / 取消 / 保存），与销售单「只留取消+保存」不一致。
3. 编辑明细用的是 `<table class="data-table">` + `mini-input`，手机端要靠 `nth-child` 拆表（旧方案，已废弃）。
4. `</style>` 之后还残留一段 `.modal-*` 死样式（从未生效）—— 顺手清掉。

### 迁移步骤

1. **引入两件**：`import { useEditMode } from '../../composables/useEditMode'`、
   `import EditModePanel from '../../components/EditModePanel.vue'`。
2. **脚本改造**：删掉本地 `showEdit` / `startEdit` 里的 `showEdit.value = true`，
   改用 `const { showEdit, saving, startEdit, closeEdit } = useEditMode({ scrollSelectorOnStart: '.edit-page' })`；
   `beginEdit()` 里拷完副本后 `await startEdit()`。
3. **模板改造**：把 `<div v-if="showEdit" class="edit-page">…</div>` 整块换成 `<EditModePanel :model-value="showEdit" :saving="saving" @cancel="closeEdit" @save="onSaveEdit">…</EditModePanel>`。
4. **按钮条**：删掉 `btn-back` 那颗（返回语义交给 `<PageActions v-if="!showEdit">`），
   取消改绑 `@cancel="closeEdit"`（原来是直接 `showEdit=false`，不会滚动回返回键）。
5. **明细改卡片**：`<table class="data-table">` → `.ec-list` / `.ec-item` 卡片（见「Quick Start」骨架），
   手机端不再拆表。
6. **清死样式**：删掉 `</style>` 之后那段 `.modal-*`；同时删掉 scoped 里旧的
   `.edit-page` / `.edit-header` / `.edit-items` / `.edit-footer` / `.edit-note-row` / `.edit-total-label` 规则
   （这些已由 `EditModePanel` 提供，留着会和组件样式打架）。
7. **保存逻辑**：成功后 `await closeEdit()` 再 `await loadOrder()`（原来是 `showEdit.value = false` + `loadOrder()`，
   没有滚动，关掉后视口会停在空白）。

### 迁移后效果

- 电脑端：编辑模块内联在详情页里，与「商品明细 / 入库进度」等卡片同宽，不再突兀全屏。
- 手机端：整屏覆盖 + 底部「取消 / 保存」常驻（和销售单一致）。
- 取消 / 保存后模块关闭 → 详情页橘色「返回」键自动出现并滚进视野。

## 七、注意事项（踩过的坑）

1. **CSS 必须写在 `<style>` 块内** —— 写在 `</style>` 之后的文本浏览器收不到（采购单现在就残留了这么一段 `.modal-*`）。
2. **`noUnusedLocals: true`** —— 模板里用 `$emit` 时，脚本里别写 `const emit = defineEmits(...)`，否则 `vue-tsc` 构建失败。
3. **同文件一次只改一处**，改完立刻 grep 校验落盘（并发写会互相覆盖，出过两次只落一条）。
4. **`closeEdit()` 的滚动目标默认 `.page-actions`** —— 页面若没用 `PageActions` 组件，需显式传 `scrollSelectorOnClose`。
5. **测试只加/只改，不删、不 skip、不放宽断言**；把销售单自身切到 `EditModePanel` 属于另一件事，
   需要先同步 `tests/sale-order-mobile-cards.test.ts`（该文件靠 grep `SaleOrderDetailView.vue`
   的 `.edit-footer` / `closeEdit` / `btn-back` 等字符串断言），本次未做。
6. **发版记得改 `package.json` 的 version** —— 漏改会让 sw.js 缓存名不更新，老用户拿不到新版。
