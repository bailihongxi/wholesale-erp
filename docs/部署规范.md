# 部署规范（V2.1-2.36起严格执行）
---
## 历史踩过的坑（全部规避）：
| 问题现象 | 根本原因 | 规避方法 |
|---|---|---|
| 推了代码但线上永远不更新 | 代码全推到main分支，GitHub Pages读的是gh-pages分支 | 必须将dist目录强制推送到gh-pages分支，仅推main永远不生效 |
| 部署后用户看到的还是旧版本，版本号不变 | 只改了src/version.ts里的显示版本号，没改package.json里的version，导致sw.js的CACHE_NAME不变，浏览器SW一直用旧缓存 | 每次部署必须同时改src/version.ts和package.json里的版本号，两者必须一致 |
| 强刷多次还是旧版本，SW缓存锁死 | 构建时没清空vite缓存，dist里的JS/CSS hash文件名和线上一样，SW直接返回旧缓存 | 每次部署前必须删node_modules/.vite和dist目录，重新构建，生成新hash文件名 |
| 部署后登录页样式乱了，纯文字无样式 | 旧SW拦截了新CSS文件请求，返回404 | 部署完成后必须curl线上sw.js，确认CACHE_NAME是新版本，否则用户切换时会出现临时样式丢失 |
| 推送时连不上GitHub，重复推错文件 | 网络超时后重试，dist目录里残留旧git仓库，推上去的是旧文件 | 每次推送前删除dist里的.git目录，全新init再推，保证dist是干净的最新构建产物 |
| 构建报错没发现，推上去的是旧包 | npm run build失败了还继续推送 | 构建必须退出码为0才能继续推送，构建报错必须先修复再部署 |

---
## 标准部署步骤（每次必须严格按顺序执行）：
1. **改版本号**：
   - src/version.ts：APP_VERSION改成新版本，APP_RELEASE_DATE改成当天日期
   - package.json：version同步改成相同版本（不带V前缀）
2. **清空缓存**：
   ```bash
   rm -rf node_modules/.vite dist
   ```
3. **构建生产包**：
   ```bash
   npm run build
   ```
   构建必须成功（退出码0），失败则停止部署，先修复错误
4. **验证本地dist**：
   ```bash
   grep "BUILD_VERSION" dist/sw.js
   ```
   确认sw.js里的版本号和package.json一致
5. **推送gh-pages**：
   ```bash
   cd dist
   rm -rf .git
   git init
   git add -A
   git commit -m "V版本号 本次更新内容"
   git push --force https://github.com/bailihongxi/wholesale-erp.git main:gh-pages
   ```
6. **线上验证（必做，不能跳过）**：
   ```bash
   curl -s "https://bailihongxi.github.io/wholesale-erp/sw.js?t=随机数" | grep "BUILD_VERSION"
   ```
   确认线上sw.js版本号是新的，才算部署完成

## 部署后用户侧说明：
部署完成后用户需要按Ctrl+Shift+R强刷一次，激活新SW加载新版本，之后自动更新，不用再手动强刷。
