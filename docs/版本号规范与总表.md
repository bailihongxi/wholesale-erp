一句话：**改错走 `.1 .2 .3`，加功能走 `-2 -3 -4`。**

**为什么 `package.json` 是 `2.1.3` 而不是 `2.1.1.2`**：npm / semver 只接受三段编号，
而 Service Worker 的缓存名由这个值派生、**必须每次发版都变**（不变就等于没发版，老用户永远拿到旧页面）。
故用 patch 位承载修订号：`V2.1-1.N` → `2.1.(1+N)`。

线上怎么核对：`curl -s "https://bailihongxi.github.io/wholesale-erp/sw.js?t=$(date +%s)" | grep BUILD_VERSION`
（注意 Pages 有 1~2 分钟延迟，等约 75 秒再查；**不要 grep `erp-x.y.z` 字面量**，那是旧的核对方式）。

## 5. 发版收口清单（**6 处，缺一不可**）

1. `src/version.ts` → `APP_VERSION`
2. `package.json` → `version`（**必须变**，否则 SW 缓存名不变、老用户拿不到新版）
3. `PRD.md` 头部产品版本 + 代码基线
4. `MENU_SPEC.md` 头部
5. `DEV_PLAN_V2.md` 头部 + 文末追加本轮章节
6. `tests/stock-cards-v17.test.ts` 版本断言

外加：`git tag -a` 打标签、推 `main` 与 tag（**tag 必须单独推**）、
`./scripts/deploy-gh-pages.sh https://github.com/bailihongxi/wholesale-erp.git gh-pages`、等约 75 秒复验线上版本。

## 6. 历史版本号不要改

`V1.0-x`、`V2.0-x` 是**历史记录**（各文档里的「XX 规范（V2.0-18 确立）」「来源：V2.0-25」等），
它们标的是**出处**而不是当前版本，保持原样以便追溯。
本规范只统一「**当前版本**」的表述方式。
